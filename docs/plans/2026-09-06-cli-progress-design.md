# CLI-13 传输进度设计

目标：读写/Loader 上传显示当前传输量、总量、百分比、平均速度、已用时间与预计剩余时间，结束保留总用时。参考用户给出的 ProgressBar 的信息布局，采用单调时钟和有界刷新，不依赖 Windows P/Invoke。基线 a3c33a7，用户 cust.img 保持未跟踪。

ProgressRecord 保留原三参数构造，增加单位（默认 Steps、显式 Bytes）和阶段（Running/Started/Completed）。旧的连接步骤仍显示计数，不能按 Bytes/s 解释。新增传输报告明确开始/完成；完成在最终 ACK/协议处理成功之后发布，异常不伪造完成。

Qcom 同步/异步读写门面共用传输进度适配器。读取使用请求字节长度；写入从已有 Raw/Sparse 计划取得实际传输长度（含发送的补齐字节），不再把分区容量当成总量。内部进度接口传递计划总量，无需重开文件、重解析或物化镜像，也不更改 IProgress<long> 公共接口。Sahara 上传标记字节与开始/完成阶段。擦除只有 ACK，保留真实步骤信息，不模拟字节吞吐。

CLI 将计算/格式化放到独立 ProgressDisplay，用可注入 TimeProvider 的单调时间戳计时。Started 重置每次操作；日志清行不重置计时。速度为当前字节/本次已用时，ETA 基于同一平均速度，零时间/未知总量不输出 NaN/Infinity。完成显示累计总用时，跨天不截断小时数。

终端最多每 100 ms 刷新一次，重定向输出最多每秒一行；开始与完成强制输出，重复完成抑制。格式化在节流后进行，避免逐包构造字符串。重定向输出不含 ANSI 控制符；窄终端缩短/省略条形部分并按显示宽度清理换行，日志、提示和进度继续共享 ConsoleUi 锁。新增用户文本全部中英文资源化。

测试先行：固定时间源验证速度/耗时/ETA、连续操作重置、节流与完成不遗漏、未知/零总量、超量钳制、连接步骤单位、重定向无 ANSI；模拟传输验证 named Raw 小文件总量、Sparse 计划长度、读写最终 ACK 后完成及 NAK 无完成。完整 Qcom/CLI 测试、Release 构建、diff/资源审查后按 Core/CLI 两个能力提交。未操作硬件，实际终端和设备吞吐仍需用户复测。
