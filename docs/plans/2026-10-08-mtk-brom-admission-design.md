# MTK BROM 接入与断连审查设计

日期：2026-10-08。任务：BROM-REC-01～04。用户已确认：默认持续等待，显式等待超时生效；识别后不自动重放认证、DA 或存储操作。

## 目标与边界

- 只处理 MTK BROM、MTK CLI 接入及其失败展示，不修改 exp、策略顺序、载荷、其他协议线路或公共 USB 传输语义。
- 默认 MTK 发现持续到取消；自动识别尚未选定协议时同样允许持续等待。显式 `--device-wait-timeout` 保留有限预算，其他显式协议的默认预算不变。
- USB 枚举/打开阶段的 USB、I/O 和设备打开状态错误可释放后重等；配置校验、驱动安装/依赖、歧义选择、资源错误不吞掉，不循环弹 UAC。
- BROM 接入界限是完整有效 FD 硬件标识，而不是 USB Open，也不是 DA StorageReady。FD 之前仅 CDC/握手/FD 查询可在新连接上重试；FD 之后即使 WDT/安全信息查询失败，也不自动再试。
- 初始握手错误必须显式标记，不能以 TimeoutException 或 IOException 包住整个 ConnectAsync 后重试。核心不加入自动重试；CLI 释放旧会话/传输后才重新发现。

## 已知线路与所有权

- 当前 Open 的 NoDevice 被重试，其他枚举/打开失败和 Probe 超时会退出；交互 DA 路径选择之前已有 Probe/WDT，非交互则在 ConnectAsync 内 Probe。
- 保持 Open → CDC → 握手 → FD → 已知 WDT ACK → 安全/版本查询 → DA 路径选择 → 同一 Probed 会话 ConnectAsync。不重放 WDT、认证、DA、扩展或读写。
- 增加具体 MtkProtocol 的历史识别标记，仅作接入恢复边界，不代表设备仍在线或认证成功；不改变 IMtkProtocol 契约、异常类型或既有状态枚举值。
- 失败候选独占释放协议与传输；成功后交还既有宿主生命周期。等待取消不降级成 USB 重试。明确预算覆盖一次等待及所有初始握手重试，成功 Probe 后解除接入预算，DA 选择/连接仍用自身有限预算。

## 超时、进度和日志

- MtkWire 每次逻辑 Read 使用一个单调时钟绝对截止时间，分片不重新获得完整 read timeout；每次同步调用返回后再次检查取消/操作预算，过期结果不能被当成成功。
- 纯 ReceiveData 失败也标记 I/O 尝试并 Fault/Close/递增代数；HasWritten 保留给永久写/Scatter 的未知写入结果分类，不与读取混淆。
- 默认有限前缀预算从 4 修为 5，允许完整 READY 后接 5F；不添加同一句柄 A0 重发或无限排空。
- 不以超时断言设备已拔出；底层 NoDevice 才展示断连，超时展示响应超时、操作停止与重新连接。同步 native 调用不能被强制中断，返回时立即传播失败，不添加重复写或异步读取线程。
- MTK 交互会话 Faulted 后停止命令循环；清除失败操作的显示与进度统计状态，不继续显示“读取中”。非 MTK 展示行为不变。
- USB 发现与初始握手各最多一条可见重等提示，初始等待提示同样去重；详细原因限 Debug，无原始帧或敏感材料；成功/终止各由拥有上下文的层汇报。
- 显式 MTK/未定协议的首次发现也使用链接取消预算，避免 Windows monitor 与 native discovery 各自重置等待时限。MTK 驱动准备计入该显式预算，但取消/终止受操作系统限制，不承诺回滚驱动变化；显式其他协议维持原默认和准备预算。
